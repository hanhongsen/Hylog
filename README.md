# Hylog

## 项目简介

Hylog（嗨，老己）是一个基于大语言模型（Large Language Model）的 AI Agent 系统，其核心目标是通过人与 AI 的自然对话，实现对用户人格的动态建模与压缩，并最终将用户匹配到中国历史上的著名人物（清朝或之前），从而帮助用户更深层次地认识自己。

Hylog 这个名字来源于 "Hi + Log（记录）"，寓意"记录真实的自己，同时以一种轻松的方式与自我对话"。

系统的最终目标不是做传统心理测试，而是构建一个"动态人格认知系统"：用户通过少量但高信息密度的回答，被 AI 逐步压缩成一个稳定的人格向量（Personality Vector），并在庞大的人物数据库（可扩展至上万角色）中找到最相似的代表人物。系统整体采用 AI 主导决策（70%~90% AI 参与度）的设计方式，由 AI 负责问题选择、模块切换、人格推理与结果解释，而程序部分负责状态管理与计算执行，从而实现"低延迟+高智能"的混合式 Agent 架构。

## 🚀 快速开始（Quick Start）

### 环境要求

- **Python** ≥ 3.10（开发环境为 3.14.5）
- **Node.js** ≥ 18（开发环境为 v24.15.0，含 npm）
- **智谱 AI API Key**：到 https://open.bigmodel.cn/usercenter/proj-mgr/apikeys 注册获取（免费模型 `glm-4-flash` 不消耗余额）

### 第一步：克隆项目

```bash
git clone https://github.com/hanhongsen/Hylog.git
cd Hylog
```

### 第二步：配置环境变量

项目根目录的 `.env` 文件包含 API Key 等敏感信息，**不会上传到 Git**（已被 `.gitignore` 忽略）。你需要基于模板手动创建：

```bash
cp .env.example .env      # Windows 用: copy .env.example .env
```

然后用编辑器打开 `.env`，至少填写以下两项：

```ini
# 智谱 API Key（必填，填你自己的 Key）
ZHIPU_API_KEY=你的智谱API Key
# 使用免费模型（不消耗余额，推荐）
ZHIPU_MODEL=glm-4-flash

# 是否使用 Mock 模式：false=真实调智谱（推荐），true=不调智谱用合成数据
USE_MOCK_AGENT=false
```

> 💡 `.env.example` 里有所有配置项的详细注释，可按需调整。

### 第三步：启动后端（FastAPI）

```bash
# 安装 Python 依赖（建议先建虚拟环境）
pip install -r requirements.txt

# 启动后端服务
python main.py
```

启动成功后会看到：
```
Uvicorn running on http://127.0.0.1:8000
```
后端 API 文档：http://127.0.0.1:8000/docs

### 第四步：启动前端（React + Vite）

> ⚠️ **重要**：前端的 `node_modules` 目录**不会上传到 Git**（体积大且平台相关），克隆后必须先安装依赖。

```bash
cd frontend
npm install        # 安装前端依赖（首次必做，会生成 node_modules）
npm run dev        # 启动前端开发服务器
```

启动成功后会看到：
```
VITE v8.x  ready in xxx ms
➜  Local:   http://localhost:5173/
```

### 第五步：访问应用

浏览器打开 **http://localhost:5173** 即可使用。

> 前端通过 Vite 的 proxy 把 `/api/*` 请求转发到后端 `127.0.0.1:8000`，所以**两个服务都要运行**，且后端要在 8000 端口。

### 常见问题

| 问题 | 解决方案 |
|------|---------|
| `npm run dev` 报模块找不到 | 没运行 `npm install`，在 `frontend/` 目录下执行一次 |
| 后端报 `ZHIPU_API_KEY 未配置` | 没创建 `.env` 或 Key 没填，回到第二步 |
| 后端报 `1113 余额不足` | 把 `.env` 的 `ZHIPU_MODEL` 改成免费的 `glm-4-flash` |
| 前端能打开但对话无响应 | 后端没启动，或不在 8000 端口 |
| 端口被占用 | 改 `.env` 的 `API_PORT`，或结束占用进程 |

## 核心架构设计

### 架构概览

```
┌─────────────────────────────────────────────────────────────┐
│                      用户对话                                │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│              11 维问题模块（探测手段）                        │
│  社交互动、情绪体验、决策风格、价值取向、自我认知            │
│  人际信任、压力应对、创造探索、亲密关系、成就动机、生活态度  │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│              OCEAN 5 维人格向量（存储状态）                   │
│        O(开放性) C(责任心) E(外向性) A(宜人性) N(神经质)     │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    人物匹配                                  │
│         主匹配：OCEAN 相似度                                 │
│         辅助判断：11 维数据区分相似人物                      │
└─────────────────────────────────────────────────────────────┘
```

### 两层维度设计

| 维度类型 | 数量 | 作用 | 来源 |
|----------|------|------|------|
| **问题维度** | 11 个 | 探测用户人格，生成问题 | 基于心理学理论设计 |
| **人格向量** | OCEAN 5 维 | 存储人格状态，匹配人物 | 心理学标准模型 |

## 问题维度设计

系统引入"模块化认知结构"，将问题空间划分为十一个模块：

| 维度 | 权威理论支撑 | 探索内容 |
|------|-------------|----------|
| **社交互动** | Big Five 外向性 (E) | 社交偏好、能量来源、人际关系 |
| **情绪体验** | Big Five 神经质 (N) | 情绪敏感度、调节能力、稳定性 |
| **决策风格** | Big Five 责任心 (C) | 决策方式、风险偏好、执行力 |
| **价值取向** | Big Five 开放性 (O) + 宜人性 (A) | 人生目标、道德判断、价值排序 |
| **自我认知** | Big Five 神经质 - 自我意识 | 自我理解、自我接纳、自我反思 |
| **人际信任** | Big Five 宜人性 (A) + HEXACO 诚实谦逊 | 信任他人、合作倾向、同理心 |
| **压力应对** | Big Five 神经质 (N) + 责任心 (C) | 应对策略、抗压能力、恢复力 |
| **创造探索** | Big Five 开放性 (O) | 好奇心、想象力、接受新事物 |
| **亲密关系** | 依恋理论 (Bowlby) | 依恋风格、亲密需求、情感表达 |
| **成就动机** | McClelland 三种需要理论 | 追求成功、目标设定、野心 |
| **生活态度** | 乐观主义研究 | 乐观/悲观、生活满意度、人生意义 |

由 AI 根据当前人格状态动态选择最合适的模块进行探索，而不是固定问卷顺序。

## 人格向量设计

系统采用 OCEAN 5 维人格向量作为核心存储格式：

| 维度 | 名称 | 含义 | 评分范围 |
|------|------|------|----------|
| **O** | Openness（开放性） | 好奇心、创造力、接受新事物 | 0.0 ~ 1.0 |
| **C** | Conscientiousness（责任心） | 自律、计划性、目标导向 | 0.0 ~ 1.0 |
| **E** | Extraversion（外向性） | 社交活跃度、能量来源 | 0.0 ~ 1.0 |
| **A** | Agreeableness（宜人性） | 合作性、同理心、信任他人 | 0.0 ~ 1.0 |
| **N** | Neuroticism（神经质） | 情绪稳定性、焦虑敏感度 | 0.0 ~ 1.0 |

**精度**：0.01（100 个等级）

**理论覆盖度**：约 92%-95%

## 人格更新算法

### 更新方式

采用 **AI 动态判断** 方式，AI 分析用户回答后输出对每个 OCEAN 维度的影响值。

### 更新算法

使用 **贝叶斯更新 + EWMA（指数加权移动平均）** 结合的方案：

| 算法 | 作用 |
|------|------|
| 贝叶斯更新 | 根据新证据更新概率分布，处理不确定性 |
| EWMA | 平滑历史数据，避免剧烈变化 |

### 更新参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 学习率 | 0.2 | 控制新数据的影响程度 |
| 最大变化幅度 | 0.05 | 限制单次更新的最大变化 |
| 最小更新阈值 | 0.01 | 小于此值的变化不更新 |
| 不确定性减少量 | 0.1 | 每次更新减少的不确定性 |

### 算法特点

- 不需要大量数据训练
- 参数可预设，后续根据效果微调
- 支持平滑更新，避免人格剧烈波动

## 收敛判断机制

### 问题数量不固定

系统采用动态对话模式，问题数量不固定，取决于人格画像是否完整收敛。

### 收敛条件（必须同时满足）

| 条件 | 说明 | 阈值 |
|------|------|------|
| 最小对话轮次 | 确保足够信息量 | ≥ 15 轮 |
| 维度覆盖率 | 每个维度至少被探索 | ≥ 2 次/维度 |
| 不确定性分布 | 所有维度不确定性降低 | < 0.3 |
| OCEAN 稳定性 | 连续多轮变化小 | 变化 < 0.05，连续 3 轮 |
| 11 维稳定性 | 连续多轮变化小 | 变化 < 0.05，连续 3 轮 |

### 避免局部最优

| 策略 | 说明 |
|------|------|
| 最小问题数量 | 强制至少 15 轮对话 |
| 维度覆盖率检查 | 确保每个维度都被探索 |
| 不确定性分布检查 | 所有维度不确定性都要降低 |
| 强制探索未覆盖维度 | 优先探索高不确定性维度 |
| 随机探索 | 10% 概率随机选择维度，避免过早收敛 |

## 收敛与兜底机制

### 设计原则

人物匹配**只使用 OCEAN 五维**，不涉及 11 维数据（11 维仅用于探索次数和不确定性跟踪）。收敛后直接匹配输出，不再做额外的相似度验证——因为人物库足够大时，OCEAN 相似度自然就高，不会出现"匹配不到像的人"的情况。

### 收敛后流程

```
┌─────────────────────────────────────────────────────────────┐
│                    收敛判断                                  │
│  （最小轮次 + 维度覆盖率 + 不确定性 三项全部满足）            │
└─────────────────────────────────────────────────────────────┘
                              ↓
         ┌────────────────────┴────────────────────┐
         ↓ 已收敛                                   ↓ 未收敛
┌─────────────────┐                    ┌─────────────────┐
│   匹配人物      │                    │   继续对话      │
│   （OCEAN）     │                    │   探索新维度    │
│   输出结果      │                    └─────────────────┘
└─────────────────┘
```

### 兜底策略（防止无限循环）

| 情况 | 处理方式 |
|------|----------|
| 正常收敛 | 匹配人物，输出结果 |
| 达到最大轮次（30 轮）| 强制匹配当前最佳人物，标记 `forced=True` |
| 用户回答无效 | 跳过本轮，返回引导语，不增加轮次 |
| LLM 调用失败 | 问题生成用备用问题；人格分析跳过本轮 |

## 数据库设计

### 数据库表结构

系统共设计 7 张数据库表：

| 表名 | 说明 |
|------|------|
| **User** | 用户表，存储用户基本信息 |
| **Session** | 会话表，存储每次测试会话 |
| **Message** | 对话记录表，存储每轮对话 |
| **PersonalitySnapshot** | 人格快照表，记录人格演化 |
| **Result** | 结果表，存储匹配结果 |
| **VerificationCode** | 验证码表，支持验证功能 |
| **Character** | 人物库表，存储人物数据 |

### 用户认证系统

支持三种登录方式：

| 登录方式 | 说明 |
|----------|------|
| 手机号 + 密码 | 主登录方式 |
| 手机号 + 验证码 | 快速登录 |
| 微信/QQ 登录 | 第三方登录 |

### 数据库技术选型

| 阶段 | 推荐数据库 | 理由 |
|------|-----------|------|
| 开发阶段 | SQLite | 简单、零配置、开箱即用 |
| 上线阶段 | MySQL / SQL Server | 性能更好、支持并发 |

## 完整工作流程

```
1. 开始对话（固定开场白，首维度 social）
       ↓
2. AI 选择问题维度（基于不确定性分布）
       ↓
3. AI 生成问题，用户回答
       ↓
4. AI 分析回答，输出 OCEAN 变化值
       ↓
5. 更新 OCEAN 五维 + 11 维（探索次数/不确定性）
       ↓
6. 检查收敛条件
       ↓ (未收敛 且 轮次 < 30)
   ┌───┴───┐
   │ 继续对话
   └───┬───┘
       ↓ (已收敛 或 达到 30 轮上限)
7. 匹配人物库（只用 OCEAN 五维余弦相似度）
       ↓
8. 输出结果
```

## 四大核心模块

### 1. Agent 调度模块

负责整个系统的流程控制与决策，作为"控制中心"协调所有模块的调用与状态流转。采用纯 Python 状态类方案（`AgentState` + `ConversationAgent`），不依赖任何流程框架。

**已完成的代码文件**：

| 文件 | 说明 |
|------|------|
| `src/agent/state.py` | AgentState 会话状态定义、序列化、阈值常量 |
| `src/agent/nodes.py` | 8 个流程节点函数 + 5 个 Mock 人物数据 |
| `src/agent/graph.py` | ConversationAgent 主控制器（编排 + 路由 + 持久化） |
| `src/agent/__init__.py` | 模块导出 |

### 2. 问题模块系统

将问题划分为十一个认知领域，允许 AI 在模块内动态生成高区分度问题。

### 3. 人格建模模块

基于 OCEAN 模型对用户回答进行向量化与稳定化处理，使人格状态可持续收敛。

**已完成的代码文件**：

| 文件 | 说明 | 代码行数 |
|------|------|----------|
| `src/personality/ocean.py` | OCEAN 模型定义 | ~290 行 |
| `src/personality/model.py` | 人格向量数据结构 | ~590 行 |
| `src/personality/updater.py` | 人格更新器 | ~420 行 |
| `src/data/models.py` | 数据库模型 | ~280 行 |

### 4. 人物匹配模块

通过 OCEAN 五维余弦相似度将用户人格与人物库进行匹配，输出最匹配的角色标签。

## 系统特点

Hylog 不是传统问卷系统，也不是简单聊天机器人，而是一个基于：

- **模块路由（Modular Routing）**
- **人格向量压缩（Personality Compression）**
- **动态收敛判断（Adaptive Convergence）**

的 AI Agent 系统。

核心价值：通过少量交互，实现对用户人格的高维建模，并将其映射到中国历史上的典型人物，从而帮助用户在对照历史人物的过程中实现自我认知与理解。

## 技术栈

- **AI Agent**：纯 Python 状态类（AgentState + ConversationAgent）、流程编排
- **LLM**：智谱 AI GLM-5.2、Prompt Engineering
- **人物匹配**：OCEAN 五维余弦相似度
- **后端**：Python、FastAPI、SQLAlchemy
- **数据库**：SQLite（开发）/ MySQL（生产）
- **前端**：Streamlit → React（后续升级）
