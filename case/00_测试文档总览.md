## 二、被测系统（SUT）范围

### 系统定位
Hylog 是一个基于 LLM 的 AI Agent 人格建模系统：通过自然对话动态建模用户 OCEAN 五维人格，收敛后用余弦相似度匹配到中国历史人物（清朝或之前）。

### 测试边界

| 层 | 范围 | 是否纳入本轮 BDD |
|----|------|------------------|
| **后端 API（FastAPI）** | 5 个核心接口 + 健康检查 | ✅ 重点 |
| **Agent 调度流程** | ConversationAgent（start / reply / _finish 状态机） | ✅ 重点 |
| **人格建模** | OCEAN 更新、smooth_update、收敛判断 | ✅ 重点 |
| **人物匹配** | 余弦相似度、热度等级、Top-K | ✅ 重点 |
| **问题生成** | LLM 生成 + fallback、维度选择策略 | ✅ 重点 |
| **Mock 模式** | USE_MOCK_AGENT=true 的合成闭环 | ✅ 重点（不依赖智谱） |
| **前端（React）** | Landing / Chat / Result 三页 + zustand store | ✅ 端到端场景（手工/Playwright） |
| **LLM 真实调用** | 智谱 GLM-4-flash | ⚠️ 仅少量契约/降级测试，不做正确性穷举（不可重复） |
| **用户认证** | 手机号/验证码/第三方登录 | ❌ 本期未实现，暂不纳入 |
| **付费分层** | is_paid_locked 字段裁剪 | ❌ 当前全开放，暂不纳入 |

## 三、BDD 方法论

### 为什么用 BDD
- Hylog 的核心价值是"对话流程 + 人格演化 + 人物匹配"的**行为正确性**，而非单个函数的正确性。
- BDD 用 **业务可读的 Given-When-Then** 描述行为，便于产品/开发/测试对齐"系统应该做什么"。
- 用例与代码解耦：即使重构内部实现（如把 Agent 换成 LangGraph），用例仍然有效。

### 用例组织（Feature 划分）
按"用户旅程 + 系统模块"双维度组织，共 **12 个 Feature**：

| # | Feature | 覆盖模块 | 类型 |
|---|---------|---------|------|
| F1 | 健康检查与基础设施 | API 入口 | 契约 |
| F2 | 创建会话 | POST /sessions | 功能 |
| F3 | 对话推进（有效回答） | POST /reply + 人格更新 | 核心功能 |
| F4 | 无效回答与降级 | skipped / LLM 失败 fallback | 异常 |
| F5 | 收敛判断 | check_convergence | 核心算法 |
| F6 | 兜底：最大轮次强制结束 | MAX_ROUNDS | 异常 |
| F7 | 人物匹配 | 余弦相似度 + 热度 | 核心算法 |
| F8 | 只读查询接口 | GET /state /result /messages | 功能 |
| F9 | 错误处理与状态码 | 404/409/422/503/500 | 契约 |
| F10 | Mock 模式完整闭环 | USE_MOCK_AGENT=true | 集成 |
| F11 | 会话持久化与恢复 | state_json / restore | 集成 |
| F12 | 前端端到端用户旅程 | Landing→Chat→Result | E2E |

### 优先级定义
- **P0（冒烟/阻塞）**：不通就阻塞发布的主路径。
- **P1（核心）**：系统核心价值，必须通过。
- **P2（重要）**：异常、边界、降级。
- **P3（补充）**：非功能性、展示、罕见路径。

## 四、关键风险与已知偏差（测试专家提醒）

> 以下偏差在通读代码后发现，**测试用例一律以代码实际行为为预期**，并在用例中标注。建议产品确认是否需要修正代码或文档。

1. **`tests/` 目录下 5 个测试文件全部为空（0 行）**，`src/agent/router.py`、`src/utils/config.py` 也是空文件。当前真实测试仅 `test_api.py`、`test_llm.py`、`scripts/verify_mock_flow.py`、`scripts/test_real_flow.py`。**单元测试覆盖率几乎为 0**，本轮 BDD 用例可作为补齐起点。

2. **收敛条件（代码 vs README）**：代码实际只校验 `总探索次数≥15` 且 `OCEAN 平均不确定性<0.3`；README 描述的"每维度≥2次探索""OCEAN 连续 3 轮变化<0.05""11 维连续 3 轮变化<0.05"**均未实现**，`min_explore_per_dimension` 参数已废弃。详见 Spec §5.3。

3. **更新参数（代码 vs README）**：`MAX_CHANGE_PER_UPDATE=0.08`（README 写 0.05）、`UNCERTAINTY_REDUCTION=0.2`（README 写 0.1）、并存在 README 未提及的"边缘减速"机制。详见 Spec §5.2。

4. **维度选择策略（代码 vs README）**：代码为"高不确定性>0.3 优先 → 低探索<2 优先 → 全随机"；README 描述的"10% 概率随机探索"**未实现**（实际是兜底情况才纯随机）。详见 Spec §4.2。

5. **LLM 不可重复**：真实模式依赖智谱返回，每次 delta 不同，无法写确定性断言。策略：算法层（updater/matcher）用确定性单测；Agent 层用 Mock 模式做集成断言；真实模式只做"流程跑通 + 不抛异常 + 字段齐全"的弱断言。

## 五、执行入口（速查）

| 目的 | 命令 | 依赖 |
|------|------|------|
| 跑现有 Mock 闭环 | `python scripts/verify_mock_flow.py` | 无需 API Key |
| 跑现有真实流程 | `python scripts/test_real_flow.py` | 需 `ZHIPU_API_KEY` |
| 跑 LLM 连通性 | `python test_api.py` | 需 `ZHIPU_API_KEY` |
| 启动后端 | `python main.py` | `pip install -r requirements.txt` |
| 启动前端 | `cd frontend && npm install && npm run dev` | Node ≥ 18 |

> 本轮 BDD 用例的**可执行化映射**（pytest 实现 / Playwright 脚本）见 `03_测试矩阵与执行指南.md` §5。
