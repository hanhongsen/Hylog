# 测试矩阵与执行指南

> 本文档把 `02_BDD测试用例_Gherkin.md` 的 76 个场景落地为可执行计划：测试矩阵、环境与数据准备、分层执行步骤、自动化映射骨架。
> 编号规则：`T-{Feature号}-{场景号}`，与 Gherkin Scenario 一一对应。

---

## 1. 测试类型分层

| 类型 | 目标 | 工具 | 速度 | 可重复性 |
|------|------|------|------|---------|
| **单元测试（Unit）** | 算法层确定性逻辑（updater / matcher / state 序列化） | pytest | 快（ms） | 高（纯函数） |
| **接口测试（API）** | FastAPI 5 个接口契约 + 错误码 | pytest + TestClient | 快（ms） | 高 |
| **集成测试（Integration）** | Mock 模式完整闭环 + 持久化恢复 | pytest + 临时 SQLite | 中（秒） | 高（不调 LLM） |
| **真实流程（E2E-后端）** | 真实模式跑通（弱断言） | pytest（需 API Key） | 慢（分钟） | 低（依赖智谱） |
| **前端 E2E** | 浏览器三页旅程 | Playwright | 慢（秒） | 高（Mock 后端） |

```bash
# 1. Python 依赖
python -m venv .venv && source .venv/bin/activate

cd frontend && npm install && cd ..

# 3. Playwright（E2E 用）
pip install pytest-playwright
```

### 3.2 测试专用配置
```ini

USE_MOCK_AGENT=true
DB_PATH=tests/hylog_test.db          # 独立测试库，避免污染开发库
API_HOST=127.0.0.1
API_PORT=8001                        # 测试用端口
# 真实模式用例单独设置：ZHIPU_API_KEY=xxx, ZHIPU_MODEL=glm-4-flash, USE_MOCK_AGENT=false
```

### 3.3 Mock 人物库说明
- Mock 模式下人物库 = `src/agent/nodes.py:MOCK_CHARACTERS`（25 个先秦至清朝人物，**内存数据，无需建库**）。
- 真实模式下人物库 = `characters` 表（需先跑 `python scripts/build_character_db.py`）。
- **单元/接口/集成测试一律用 Mock 模式**，保证可重复、零额度消耗。

### 3.4 临时数据库策略
- 每个 API/集成测试用例使用 `tempfile.mkdtemp()` 下的独立 SQLite，setup 时 `init_global_database`，teardown 时删除。
- 避免用例间状态污染（尤其 turn_count、match_count）。

## 4. 分层执行步骤

### 4.1 第一层：单元测试（算法层，最快）
**目标**：F5 收敛、F7 匹配、F4 降级中的纯逻辑、F11 序列化。
```bash
pytest tests/unit/ -v --cov=src/personality --cov=src/matching
```
关键断言点：
- `check_convergence`：验证 D1 偏差（只看 2 个条件）。
- `smooth_update`：边缘减速、|delta|<0.01 不变、裁剪 [0,1]。
- `update_ocean`：只降有效维度不确定性。
- `cosine_similarity` / `calculate_heat_level` / `get_best_match` 相同相似度随机。
- `OCEANVector` / `Dimension11Vector` / `MatchResult` 往返序列化。

### 4.2 第二层：接口测试（TestClient）
**目标**：F1、F2、F8、F9 全部，F3/F6/F10 的 API 部分。
```bash
pytest tests/api/ -v
```
关键断言点：
- 状态码：200/422/404/409/503/500 精确匹配。
- 响应结构：符合 `schemas.py` 的 Pydantic 模型。
- 长度边界：answer = 1 / 100 / 101。

### 4.3 第三层：集成测试（Mock 闭环）
**目标**：F10、F11、F3 多轮、F6 兜底。
```bash
pytest tests/integration/ -v
```
关键断言点：
- 跑 `scripts/verify_mock_flow.py` 的逻辑（30 轮内必结束）。
- 用探针验证 `analyze_personality` 调用次数 = 0。
- restore 后 turn_count / ocean 完全一致。

### 4.4 第四层：真实模式（手动/夜间）
**目标**：F4 的 LLM 判定、真实演化。
```bash
ZHIPU_API_KEY=xxx ZHIPU_MODEL=glm-4-flash USE_MOCK_AGENT=false \
  python scripts/test_real_flow.py
```
弱断言：跑通不抛异常、OCEAN 演化、最终有结果；**不做精确数值断言**。

### 4.5 第五层：前端 E2E（Playwright）
**目标**：F12 全部。
```bash
# 后端用 Mock 模式启动
USE_MOCK_AGENT=true python main.py &
# 前端
cd frontend && npm run dev &
# 跑 E2E
pytest tests/e2e/ -v
```

### 4.6 一键全量（CI 友好）
```bash
pytest tests/unit tests/api tests/integration -v --junitxml=report.xml
# E2E 与真实模式单独 stage
```

## 5. BDD → 自动化映射骨架

### 5.1 pytest + pytest-bdd（推荐，后端用例）
将 Gherkin `.feature` 文件与 step 实现绑定。

```
tests/
├── features/                  # 直接复用 02_BDD 文档的 Gherkin
│   ├── F2_create_session.feature
│   ├── F3_reply.feature
│   └── ...
├── step_defs/
│   ├── conftest.py            # 公共 fixtures：TestClient / 临时 DB / Mock 开关
│   ├── test_F2_create_session.py
│   └── ...
├── unit/                      # 纯算法单测（不走 HTTP）
└── e2e/                       # Playwright 脚本
```

**conftest.py 关键 fixture 骨架**（示意）：
```python
import pytest, tempfile, os
from fastapi.testclient import TestClient

@pytest.fixture
def temp_db(tmp_path, monkeypatch):
    db_path = str(tmp_path / "test.db")
    monkeypatch.setenv("DB_PATH", db_path)
    monkeypatch.setenv("USE_MOCK_AGENT", "true")
    from src.data import init_global_database, get_database_url
    init_global_database(get_database_url("sqlite", db_path))
    yield db_path

@pytest.fixture
def client(temp_db):
    from src.api.main import app
    return TestClient(app)

@pytest.fixture
def session_id(client):
    r = client.post("/api/sessions", json={})
    assert r.status_code == 200
    return r.json()["session_id"]
```

**step 骨架示意**（T-3-1 有效回答推进轮次）：
```python
from pytest_bdd import scenarios, given, when, then

scenarios("features/F3_reply.feature")

@when('发起 POST /reply，请求体为 {"answer":"我喜欢一个人安静地看书"}')
def reply_one(client, session_id):
    r = client.post(f"/api/sessions/{session_id}/reply",
                    json={"answer": "我喜欢一个人安静地看书"})
    assert r.status_code == 200
    reply_one.resp = r.json()

@then("响应体 progress.turn 为 1")
def assert_turn():
    assert reply_one.resp["progress"]["turn"] == 1
```

### 5.3 Playwright E2E 骨架（F12-1 主路径）

```python
from playwright.sync_api import sync_playwright

def test_full_journey_mock():
    with sync_playwright() as p:
        page = p.chromium.launch()
        page.goto("http://localhost:5173")
        page.click("text=开始")          # Landing
```

## 7. 已知缺陷与建议（测试专家提交清单）

> 以下为通读代码时发现的、应在测试外修复的问题，建议作为缺陷或技术债录入。

| ID | 类型 | 描述 | 建议 |
|----|------|------|------|
| BUG-1 | 一致性 | README 收敛条件与代码不符（D1），用户/产品预期可能错位 | 统一文档与代码，或显式声明 |
| BUG-2 | 一致性 | README 更新参数（0.05/0.1）与代码（0.08/0.2）不符 | 同步文档 |
| BUG-3 | 缺失 | `tests/` 5 个文件全空、`router.py`/`config.py` 空文件 | 删除空文件或补实现，避免误导 |
| BUG-4 | 配置 | `CORS_ORIGINS` 默认值未含 React 5173 | 默认值改为含 5173 或文档强调 |
| BUG-5 | 健壮性 | `analyze_personality` 的 skipped 空/超长分支被 Pydantic 前置拦截，属死代码 | 确认是否保留防御层 |
| BUG-6 | 健壮性 | `_update_message_delta` 按 content 匹配最近 user 消息，相同回答会误改 | 改用 message_id 精确定位 |
| BUG-7 | 可测试性 | 真实模式无 mock 注入点，难以在 CI 中测 LLM 降级 | 在 nodes 层加依赖注入（updater/llm 可替换） |
| BUG-8 | 重复 | `test_api.py`、`test_llm.py` 散落在根目录，与 `tests/` 体系不统一 | 迁入 `tests/manual/` |
| BUG-9 | 安全 | 全局异常已防堆栈泄露，但 `detail` 仍回显原始异常字符串（routes 多处） | 生产环境返回通用提示 |
| BUG-10 | 资源 | `reply` 路由先 `load_session_or_404` 用一个 db，再 restore 用另一个 db_session，连接管理偏复杂 | 简化连接生命周期 |
| BUG-11 | 功能缺陷 | `GET /api/sessions/{id}/state` 的 `personality_state` 恒为默认 0.5：`routes.py` 读取 `state_json["ocean_vector"]` 嵌套层级错误（实际结构为 `{ocean:{openness,...}, uncertainty, metadata}`，代码用 `'openness' in ocean_vector` 判断，顶层无此键 → 永远走 else）。**已被 `test_real_flow.py` 阶段 6 实跑捕获** | 改为 `(state_data["ocean_vector"] or {}).get("ocean", {})` 再取分键 |

## 8. 缺陷管理流程建议
1. **严重度**：P0 冒烟失败 = 阻塞发布；P1 失败 = 必须修复；P2 = 可带病上线但记录。
2. **回归**：每个缺陷修复后，对应 BDD 场景加入回归集。
3. **报告**：CI 产出 `--junitxml`，在 PR 中展示通过率与覆盖率差值。
4. **真实模式**：每周夜间跑一次 `test_real_flow.py`，监控智谱额度与模型行为漂移。
